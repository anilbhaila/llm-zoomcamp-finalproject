# llm-zoomcamp-finalproject: Ecommerce Chatbot
## Problem Description
In the age of AI, people have no time to scroll through FAQs on any website. So, this is a project that leverage LLM models like GPT-5.0-mini to create interactive chat to find answers from the Ecommerce Website. The project will promptly answer users query if it exist in the website's FAQ section, so that users don't need to scroll through large FAQ page.

## Purpose
* Provide end user quick and up to date information for their questions.
* Reduce scrolling needs to search answers in FAQ page.

## 1. Dataset
   The Ecommerce FAQ data set was taken from Kaggle. https://www.kaggle.com/datasets/saadmakhdoom/ecommerce-faq-chatbot-dataset. This dataset is downloaded and added to this repository inside data folder with name Ecommerce_FAQ_Chatbot_dataset.json. It has around 79 questions and answers.

## 2. Technologies Used
### PostgreSQL
* It is used to store user queries, llm answers, user feedback, llm token cost, token usage
* Database tables can be created either from UI or Make init-db command.
### Elastic Search
* It is used to store FAQ questions, ground truth generated by LLM, and Vectors generated by Spacy and Sentence Transformer models.
* It is used to generate "documents_spacy" and "documents_st" indexes using Spacy and Sentence Transformer models respectively.
* It is also used to perform text search, vector search and hybrid search in both indexes.
### Mage
* It is used to ingest FAQ Dataset, add chunk, lemitize, add embeddings and create index in elastic search with data pipeline named Ecommerce_chatbot
* It is fully automated data processing, transformation, and loading tasks.
* This will definitely help the system's scalability and maintainablity
### Grafana
* It is used as monitoring our chat bot performance.
* We will use it to monitor LLM token cost, Response Time, Token Usage, User Feedback, Relevance Distribution.
### Streamlit
* This will be our User Interface for our Chatbot.
* It will allow Ecommerce website visitor to ask question, provide thumbs up thumbs down feedback.
* For testing, we can also initialize database,
* For testing our grafana dashbord, we can generate fake data for 60, 600 and 1800 seconds.
* Tester can select search type [text, vector, hybrid]
* Tester can also select which Embedder to use for vector and hybrid search.
### OpenAI
* We use OpenAI as our LLM model for generating responses based on retrieved context (FAQ Dataset)
* It is also used to at least five generate Ground truth for all Questions. It is like advance technique of rewriting possible users queries.
* It is also used as a LLM-as-a-judge to judge the provided response for user queries.
### Docker
* Here, postgreSQL, elastic search, mage, grafana and stremlit are seperate applications. So, to control and manage them with one file and one command we use docker.
* Each of these applications run on their own Docker containers, but we can start and stop them with one command.
* For proper system initialization, we start these containers on proper order.

## 3. Reproducibility
### Step 1: System Preparation
* Make Sure you have installed VS Code in your host machine. Then install Dev Containers Extension from microsoft. So, we can run this project with in Dev Containers. This will remove our host machine hardware limitation like old cpu architecture for newer python dependency libraries.
### Step 2: Clone the github repository
* From within VS Code Clone this reposiory.
  `git clone git@github.com:anilbhaila/llm-zoomcamp-finalproject.git`
* When you open this project in VS Code with Dev Contains extension installed, VS Code will detect the .devcontainer/devcontainer.json file and start building the docker image automatically and your vs code will open from within Dev Containers.
* It will be much similar like github codespace.

### Step 3: Create .env file
* Inside root folder where this readme file exist, you will see dotEnv.txt, you just need to copy all code from this file and paste it into .env file you just created.
* The only two things you need to update are below lines:
```
OPENAI_API_KEY=your-key-here
MAGE_TRIGGER_URL=http://127.0.0.1:6789/api/pipeline_schedules/1/pipeline_runs/4c11159a05a246939d631299f86f96b5
```
* You need to generate you OPENAI_API_KEY from Open "[https://platform.openai.com](https://platform.openai.com/login)"
* You will generate MAGE_TRIGGER_URL after you successfully run mage container and open in browser.
### Step 4: Start all Services
* run below command on VS Code terminal
```docker compose up```
* if you find any issue running these services, please allocate 80% of you CPU and 12 GB or memory to your Docker Application.
* if you see all services successfully ran then, visit urls on step 5
### Step 5: Lunching services in UI

* Mage Pipeline Explanation: Mage Container volume is mapped with host container's volume, so when mage successfully starts running Ecommerce_chatbot folder is automatically created by Mageai.
  	1. pipelines folder contains subfolder populate_elasticsearch which stores metadata.yaml file. This file is generated when i created a pipeline from mage UI. Mage will detect all pipelines already existed in this pipeline folder.
  	2. data_loaders folder contains ingest.py which extracts our Ecommerce_FAQ_Chatbot_dataset.json file and converts into dataframe
  	3. transformers folder contains chunk.py, (which add chunk into dataframe), lemmatize.py (which converts data chunk into tokens), embed.py (which create embeddings/vectors of tokens) and st_embed.py (which converts chunks to embeddings/vectors by SentenceTransformer. which is not working in pipeline due to library download issue, but it works from offline_pipeline.py existed inside app folder). I created offline_pipeline.py because my laptop hardware was not able to run both models inside mage due to lack of RAM and CPU constraints.
  	4. data_exporters folder contains index.py which takes dataframe as input from transformer embed.py and create index in elasticsearch in bulk.
 
* Note if you face an issue with running mage pipeline, you can also use ```make trigger-offline-pipeline``` command to create index within elastic search.
